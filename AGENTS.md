# Repository workflow

## Frontend and interface work

For requests that change this portfolio's user-facing pages or interface, use the relevant installed Studio Forge guidance automatically:

- Use `frontend-design` for page direction, layout, visual hierarchy, and responsive presentation.
- Use `react-ui-engineering` when a task actually involves React. This repository currently uses plain HTML, CSS, and JavaScript; preserve that stack unless the user asks to change it.
- Use `motion-design` when adding or revising interface motion.
- Use `ui-ux-review` when the user requests critique or when a substantial interface change would benefit from a review.

For substantial interface work, consult the Studio Forge MCP workflow or the specific design guidance when available. Keep small fixes lightweight. Treat guidance and MCP output as advice; make changes only within the user's request and available permissions.

Use this loop:

1. **Scope** the outcome and how to recognize completion.
2. **Shape** the approach around the existing project, content, and technical constraints.
3. **Slice** the work into the smallest useful change.
4. **See** the running interface when browser access is available, then fix the largest issue found.
5. **Ship** the requested result and describe checks actually performed.

## Portfolio-specific care

- Preserve the user's approved content, voice, and project identity.
- Do not invent experience, credentials, outcomes, client details, or project claims.
- Keep pages responsive and accessible, including keyboard use, readable contrast, meaningful labels, and reduced-motion preferences when motion is involved.
- Preserve working behavior and established URLs unless the requested change requires otherwise.

## Scope and release boundaries

Follow the user's request and repository instructions. If a request is analysis-only, do not implement it. Do not publish a deployment or make external changes beyond the action the user explicitly requested.
